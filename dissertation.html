Auto-Remediation Architecture via StackStorm

M.Tech Dissertation • Systems Reliability • 2025

Overview

In high-scale environments, manual intervention for routine service failures is a primary source of operational toil. My dissertation explored a closed-loop automation prototype designed to detect, diagnose, and resolve known service outages without human interaction.

The Workflow

The architecture uses event-driven automation to connect monitoring signals with controlled administrative actions.

Auto-remediation workflow from service detection through outcome notification.

  1. New RelicService-down detection
  2. Webhook PayloadJSON event data
  3. StackStorm EngineRule matching and logic
  4. Auto-RemediationService restart command
  5. Microsoft TeamsOutcome notification

Technical Deep Dive

When New Relic identifies that a service process has terminated or is unresponsive, it triggers a critical alert. The alert sends a POST request by webhook to the StackStorm API endpoint.

Inside StackStorm, a custom rule parses the incoming JSON. If the alert matches the known service-down pattern, an Orquesta workflow executes an approved SSH or Kubernetes-native command to restart the affected service.

Prototype Results

In the dissertation test environment, the prototype produced the following results. Production outcomes depend on infrastructure, alert delivery, and recovery-command safeguards.

Rapid Recovery

Completed the tested recovery loop in under 10 seconds, compared with a manual response measured in minutes.

Reduced Toil

Removed manual ticket handling for the known Level 1 failure scenarios included in the prototype.

Visibility

Recorded each automated action and delivered its outcome to a Microsoft Teams channel.

Reliability

Demonstrated how automated recovery can support service-availability objectives for known failure modes.
